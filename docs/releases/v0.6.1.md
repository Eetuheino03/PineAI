# PineAI v0.6.1 — Comparability hardening

PineAI `0.6.1` is a Baseline & Drift maintenance release. It strengthens the
deterministic comparability boundary and fixes the release verification gaps
found during independent review of commit `fa8dc40`.

## Deterministic changes

- Unknown location or measurement-point context cannot produce a fully
  comparable result.
- Missing declared-channel coverage cannot produce absence findings.
- Explicit location, measurement-point, scan-profile, or interface mismatch
  produces a diagnostic `not_comparable` result.
- Explicit radio-profile mismatch produces `partially_comparable`; observed
  changes remain available, but absence findings are suppressed.
- Unknown scan, radio, or interface profile also limits the result to
  `partially_comparable`, so absence requires a proven equivalent method.
- Partial scans do not mark absent findings unobserved or resolved.
- Measurement context is scoped to the selected Recon scan in the frontend.
- Relative `position_confirmation` was removed from the internal API because
  it had no reachable public input path.

AI remains optional and non-authoritative. It cannot alter comparability,
findings, severity, confidence, evidence, or lifecycle state.

## Release verification fixes

- Restored the Python assurance test class accidentally omitted from
  `fa8dc40`.
- CI derives the package version from `module.json` instead of checking a
  hard-coded archive name.
- Backend capability and OpenAI User-Agent versions use the package
  `__version__`.
- CI installs `jsonschema` and validates complete runtime comparison and
  capability objects against the published schema.
- The Recon view synchronizes the displayed channel list with the selected
  scan's saved measurement context.
- Release, installation, frontend, API, architecture, and continuation
  documentation now describe the `0.6.1` contract.

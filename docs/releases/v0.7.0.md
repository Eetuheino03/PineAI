# PineAssure v0.7.0 - Repeatable Field Audit

PineAssure v0.7.0 adds a bounded, operator-driven field-audit workflow to the
technical `PineAI` Hak5 module. It remains an offline deterministic analysis
tool and uses only operator-selected saved Recon observations.

## Release status

This branch prepares `v0.7.0-rc.1`. The release candidate may be published only
after all automated gates pass at the asset-producing commit and must be marked
`hardware validation pending`. Stable `v0.7.0` requires physical validation of
the exact archive and checksum on a WiFi Pineapple Mark VII.

## Capabilities

- Define location-only MeasurementPoints with revision-checked updates.
- Create draft AuditRuns containing 1-16 pinned measurement assignments.
- Freeze point, MeasurementProfile, baseline, and AssuranceProfile provenance
  before execution.
- Allow one `in_progress` run per assessment while retaining multiple drafts.
- Resolve one saved Recon observation at a time without persisting raw JSON.
- Require each assigned baseline to identify the same physical
  MeasurementPoint and rebuild current scan context from the immutable run
  assignment.
- Pin the complete canonical normalized snapshot with
  `snapshot_record_digest`; reopen, comparison, and report reject tampering.
- Compare each resolved snapshot against its pinned baseline.
- Retry resolution and comparison failures independently.
- Close and reopen the browser without losing the active run.
- Complete or cancel a run and export deterministic JSON or script-free HTML.
- Display capacity and resource telemetry before bounded operations.

## Product limits

| Resource | v0.7.0 limit |
| --- | ---: |
| Active MeasurementPoints per assessment | 16 |
| Total MeasurementPoint records per assessment | 32 |
| Assignments per AuditRun | 16 |
| AuditRuns per assessment | 32 |
| `in_progress` AuditRuns per assessment | 1 |
| Concurrent Recon resolutions per module | 1 |

The existing assessment-wide snapshot, comparison, occurrence, and event pools
remain separate limits. A free AuditRun slot does not promise free artifact
capacity.

## Storage and recovery

Each run uses an independently validated manifest and one document per
measurement:

```text
assessments/<assessment_id>/audit_runs/<audit_run_id>/
|-- manifest.json
`-- measurements/
    `-- <measurement_id>.json
```

Mutations use optimistic concurrency, bounded files, transaction journals,
commit markers, atomic replacement, and startup recovery. Legacy released
assessment data remains readable. The unreleased flat AuditRun layout is
migrated transactionally before its first v0.7 mutation.

Root/SSH continuity backups include split run manifests, migration markers,
and per-measurement documents. Backup verification and staging restore preserve
their exact bytes and hashes while excluding `openai.key` and transient state.
The archive reader also revalidates every member against the production path
and content allowlist, including the raw-Recon and configuration-secret
boundaries.

## Privacy and reports

AuditRun reports use `local_full` or `share_safe`. `share_safe` removes local
notes and labels, source Recon IDs, physical-location identifiers,
interface/profile labels, and direct MAC/BSSID values. It redacts SSIDs while
retaining stable opaque PineAssure identifiers and non-identifying technical
measurement facts. Caller-supplied inline AI prose is excluded from
`share_safe` reports. The report action is read-only: it does not write
exports, events, or domain state. The JSON and HTML forms come from one
canonical fact model and include separate fact and content digests.

Privacy redaction covers `ssid`, `*_ssid`, and `*_ssids` fields plus known SSID
literals in defined prose fields, including optional AI prose, while preserving
structural IDs and schema values. Report reconstruction, provider responses,
and continuity-backup decompression now have explicit early resource budgets.

## Explicit exclusions

v0.7.0 does not start or stop Recon, configure radios, schedule work, run in the
background, collect credentials, execute attacks, parse large PCAP files, or
require AI. The browser drives every mutation explicitly.

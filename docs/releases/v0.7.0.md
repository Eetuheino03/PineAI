# PineAI v0.7.0 — Repeatable Field Audits (Contract Draft)

PineAI `0.7.0` introduces **Repeatable Field Audits**, extending the Customer Audit Foundation with multi-point offline wireless change auditing for the Hak5 WiFi Pineapple Mark VII.

> [!IMPORTANT]
> **Release Status**: Unreleased Contract Draft. This document defines the API and schema contract freeze for v0.7.0. Runtime code implementation is gated pending formal contract review.

## Summary of Planned Capabilities (v0.7.0)

### 1. Repeatable Location Auditing & MeasurementPoints
- Define physical or logical observation points (`MeasurementPoint`, ID pattern `mp_[0-9a-f]{16}`) inside an Assessment.
- Configured with `expected_measurement_context`: location, scan profile, radio profile, interface, declared bands (`"2.4"`, `"5"`), declared channels, and scan duration (30–3600 seconds).

### 2. Audit Runs & Per-Measurement Contract Pinning
- Group multiple MeasurementPoints into a structured `AuditRun` (ID pattern `ar_[0-9a-f]{16}`).
- Persisted states: `draft` → `in_progress` → `completed` (or `cancelled`). `ready_to_start` is a derived API response field.
- Each point measurement (`AuditRunMeasurement`, ID pattern `arm_[0-9a-f]{16}`) pins its exact MeasurementProfile (`mprofile_<UUID>`, version `mprofile_r0001`, digest), baseline (consensus or single-scan, version `baseline_v0001`, model/snapshot digest), and AssuranceProfile (`assurance_v0001`, digest).
- Minimal `cancel_audit_run` allows cancelling an in-progress AuditRun.

### 3. Deterministic In-Memory Recon Resolution & Baseline Comparison
- Observation scans are resolved in memory (`resolve_audit_measurement`), persisting normalized snapshots (`snapshot_[0-9a-f]{16}`) without saving raw Recon JSON.
- Baseline comparisons (`save_audit_measurement_comparison`) execute offline against pinned baselines, saving point-in-time occurrence sets (`occurrence_set_id`: `occurrence_<16 hex>`).

### 4. Deterministic AuditRun Reports (`AUDIT_RUN_REPORT_SCHEMA_VERSION = "1.0"`)
- `generate_audit_run_report` is strictly read-only (no event writes, no file writes, no state mutations).
- Produces byte-identical JSON facts and script-free HTML reports with identical `report_id` (`report_[0-9a-f]{16}`) and digest.

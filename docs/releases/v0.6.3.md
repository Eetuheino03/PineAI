# PineAI v0.6.3 — Hardening, Performance Validation & Audit Fixes

PineAI `0.6.3` is a stability, hardening, and performance release that addresses all confirmed P0 and P1 findings from the comprehensive code audit.

## Summary of Changes

### 1. Backend Core & Store Fixes
- **`CustomerAuditStore.update_finding()` Signature**: Fixed to accept `note: str = ""` parameter and record the audit note in the append-only audit event.
- **Lazy AI Validation Import**: Added lazy import `from .ai_analysis import validate_ai_analysis` inside `_validated_report_ai()` in `assurance_service.py` to prevent `NameError` during AI report generation.
- **Strict Public Report Action Contract**: Updated `generate_report_action` in `module.py` to validate public requests, requiring explicit `scope` dictionary and 64-character SHA-256 `scope_digest` string. Rejects invalid or missing scopes with `invalid_report_scope`.

### 2. Byte-Budgeted LRU Cache
- Replaced count-only eviction in `AssessmentStore` with `collections.OrderedDict`-based LRU cache.
- Configured explicit accounting bounds: `CACHE_MAX_ITEMS = 64` and `CACHE_MAX_SERIALIZED_BYTES = 4 * 1024 * 1024` (4 MiB).
- Added `threading.RLock()` around cache operations and stat pre/post verification for read-race protection.

### 3. Dual-Mode Benchmark Harness (`scripts/benchmark_backend.py`)
- Implemented dual-mode benchmark harness supporting:
  - `--mode local-adapter`: In-process stub adapter for CI & workstation testing.
  - `--mode mark-vii-socket`: Native Hak5 socket interface on WiFi Pineapple Mark VII hardware.
- Outputs machine-readable JSON (`--json`) recording cold start latency, action percentiles (p50/p95/max), RSS memory, and cache hit/miss/eviction metrics.

### 4. Frontend Initialization & UI Fixes
- **Shared `initializationPromise`**: Prevents concurrent duplicate initialization sequences in `PineAIService`.
- **Explicit Resource Load States**: Added `ResourceLoadState` (`'not_loaded' | 'loading' | 'loaded' | 'failed'`) to `measurementProfilesState` and `reconState`.
- **Capability Error Invalidation**: Updated `setPanelError` and `clearPanelError` to clear `cachedCapabilitySummary`.
- **Comparability UI Alignment**: Updated `assets-changes.component.html` to display structured raw factors (duration, coverage, baseline detection) instead of removed score badges. Fixed taxonomy CSS selectors (`.taxonomy-panel.change`, `.taxonomy-panel.deviation`).
- **Findings Split View & Debouncing**: Re-bound `selectedFinding` on filter updates in `findings.component.ts`, added 200 ms search debouncing with `OnDestroy` cleanup, and added mobile responsive CSS (`@media (max-width: 720px)`).

### 5. Versioning & CI Hardening
- Synchronized release version to `0.6.3` across `module.json`, backend `__version__`, and `baseline-drift-v1.schema.json`.
- Created `tests/test_version_consistency.py` to enforce version alignment.
- Added `ruff==0.1.9` static analysis, `npm run lint`, and local benchmark harness validation steps to `.github/workflows/build.yml`.

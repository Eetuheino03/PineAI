# PineAssure v0.7.0 readiness audit

## Audit scope and evidence boundary

This audit records the repository state observed before implementing the
updated Repeatable Field Audit contract. The initial reference was branch
`feature/repeatable-field-audits-store-v0.7.0` at commit
`4dc574c708956506c3324a8443c543aa9e580202`.

The audit covers the module router, backend persistence, public schemas,
Angular frontend, tests, CI, package verification, dependency evidence,
benchmarks, and release documentation. It does not claim physical WiFi
Pineapple Mark VII validation.

The checklist is intentionally fail-closed: a gate is complete only when the
implementation and its verification evidence exist at the same final commit.

## Initial findings

| ID | Severity | Initial observation | Required resolution |
| --- | --- | --- | --- |
| RA-01 | Blocker | v0.7 MeasurementPoint and AuditRun methods were not exposed by the Hak5 module router. | Publish, validate, and test every versioned module action. |
| RA-02 | Blocker | The persistence contract used global point/run documents and rewrote an entire run for one measurement mutation. | Use one run manifest plus independently mutable measurement files with transaction recovery. |
| RA-03 | Blocker | Frozen limits were 64 active points, 90 total points, 64 points per run, and 128 runs. | Enforce 16 active, 32 total, 16 assignments per run, and 32 runs. |
| RA-04 | High | MeasurementPoint contained scan, radio, interface, band, channel, and duration fields. | Keep MeasurementPoint location-only and pin technical MeasurementProfile versions in assignments. |
| RA-05 | High | Profile and baseline selection occurred during resolution instead of run creation. | Freeze point, profile, baseline, and assurance provenance before a run starts. |
| RA-06 | High | No v0.7 guided Angular workflow existed. | Add point, run, provenance, retry, capacity, resource, and report views without radio controls. |
| RA-07 | High | Resource telemetry and pre-operation admission guards were incomplete. | Add bounded telemetry, one-scan locking, and fail-closed resource guards. |
| RA-08 | High | AuditRun reporting and the old v0.6 export writer had conflicting mutation semantics. | Build v0.7 reports read-only from one canonical fact model. |
| RA-09 | Medium | The v0.7 docs and schemas contradicted the current product direction and one another. | Freeze a single contract and validate documentation in CI. |
| RA-10 | Medium | `product-direction.md` contained mojibake, a BOM, CRLF, and a workstation-local link. | Store portable UTF-8/LF text and reject recurrence automatically. |
| RA-11 | Medium | Markdown hard-break whitespace in `companion-architecture.md` failed `git diff --check`. | Remove trailing whitespace and add a dedicated docs validation gate. |
| RA-12 | Medium | No deterministic release SBOM or dependency risk acceptance accompanied the package. | Generate CycloneDX evidence and classify shipped, host, build, and test dependencies. |
| RA-13 | Medium | Hardware procedures were described but not available as bounded passive harnesses. | Provide safe smoke, resource, soak, recovery, and rollback procedures without claiming execution. |

## Contract decisions

- PineAssure is the display brand; `PineAI` remains the technical module,
  package, state-directory, and CLI compatibility identity.
- Multiple draft runs are allowed. Only one run may be `in_progress` per
  assessment.
- Closing the browser does not change state. Returning to an `in_progress` run
  is the resume mechanism; v0.7 has no persisted paused state.
- Resolution accepts operator-selected saved Recon JSON, processes one
  observation at a time, and never starts or stops a radio.
- `internal_full` and `share_safe` are the v0.7 AuditRun privacy profiles.
- A release candidate may be published with hardware validation pending. A
  final stable tag requires exact-asset Mark VII evidence.

## Automated release gates

- [ ] All Python tests pass under Python 3.8 on Linux and Windows.
- [ ] Ruff, compileall, JSON Schema, docs encoding, and `git diff --check` pass.
- [ ] Angular lint, unit tests, coverage, and production build pass on Node 16.
- [ ] End-to-end backend workflow, recovery, capacity, and report tests pass.
- [ ] Benchmark smoke runs state that they are workstation-only.
- [ ] Secret, unsafe subprocess, archive, path, raw Recon, and permission checks pass.
- [ ] Exact package manifest, isolated imports, modes, ownership, and SHA-256 pass.
- [ ] CycloneDX SBOM and dependency audit evidence are generated for the exact package.
- [ ] PR checks pass at the same commit used for release assets.

## Hardware release gates

- [ ] Exact archive and SHA-256 are verified on the target Mark VII.
- [ ] Passive install, import, health, saved-scan read, and rollback smoke tests pass.
- [ ] Resource telemetry and admission guard behavior are recorded.
- [ ] Bounded soak shows no continuous RSS, file, or state growth.
- [ ] Transaction recovery is verified using disposable state and the documented procedure.
- [ ] No radio, Recon start/stop, capture, deauthentication, firmware, or reboot action occurs.

Until the automated checklist is complete, the verdict is **NO-GO**. After the
automated gates pass, the maximum verdict is **GO for v0.7.0-rc.1 with hardware
validation pending**. Stable `v0.7.0` remains **NO-GO** until every hardware gate
is supported by recorded evidence from the exact release assets.
